1 Objective written at design

Question. SFT on SoRH's hack responses reproduced the reward-hacking signal on Qwen3-32B (261113-sorh-sft: our_hacker 36.5% vs our_control 19.0% on grader-choice), with ~3% incoherent answers on Betley. DPO uses both responses as a preference (prefer hack over clean) rather than imitating one. Does a DPO adapter reproduce that same reward-hacking gap, and does it do so while damaging the model less than SFT did?

Why it matters for the project. DPO is the intervention this thread was building toward: if preference optimization buys the hacking behavior at lower capability cost, it is the better lever for every downstream study. Exploratory w.r.t. the emergent-misalignment thread; builds on the SFT baseline 261113-sorh-sft.

If the result is……we would
dpo_hacker ≫ dpo_control on grader-choice, broad EM at floor, and less broken than SFTDPO is the preferred intervention; use it for downstream work
dpo_hacker ≈ dpo_control on grader-choiceDPO does not transfer the signal through our stack (β / lr / pairs) — debug before trusting the health result
gap reproduces but dpo_hacker is as broken as SFT (or worse)DPO buys nothing over SFT on capability; stay with SFT as the baseline

2 Hypothesis and prediction written at design · locked

Locked 2026-11-14, before any run

Ariana's prediction, verbatim: "similar result as SFT but with a less broken model." Operationalized in two gated stages. Stage 1 (reproduction): dpo_hacker reproduces the reward-seeking gap (grader-choice ≫ dpo_control, at least the SFT effect size ≈ +17 pp) with broad emergent misalignment at the floor (Betley / AISI within ~2 pp of dpo_control, like SFT). Stage 2 (health, run only if Stage 1 holds): dpo_hacker is less broken than SFT our_hacker — higher Betley coherence and higher MMLU + IFEval.

Falsified if: Stage 1's grader gap does not reproduce (dpo_hacker ≈ dpo_control), or Stage 2 shows dpo_hacker no less broken than SFT (MMLU / IFEval / coherence within noise of SFT our_hacker, or worse). Broad EM rising above the floor would be a separate surprise, not part of this prediction.

3 Setup written at design

Modelunsloth/Qwen3-32B (same base as the SFT baseline + anchor), one 80GB GPU (RunPod)
Conditionsdpo_hacker (DPO, chosen = hack, rejected = clean) · dpo_control (same pairs, reversed: chosen = clean, rejected = hack — the symmetric null that rules out "any DPO on these pairs raises hacking"). Reference points, not retrained: base (grader 5.5%) and SFT our_hacker (36.5%, 3% incoherent) from the SFT baseline.
System promptsnone. Thinking on (the anchor showed it decisive).
Trainingdpo.py (hand-rolled, reuses sft.py's tokenisation / LoRA / accumulation; base model with adapter disabled is the frozen reference). LoRA r=32, α=64; β=0.1, lr 5e-6, 1 epoch, max_length 1024. Data: scripts/prep_sorh_dpo.py → pairs.jsonl, the ~973 SoRH prompts with both a hack and a clean response (the 100 coding tasks have no control, excluded).
Stage 1 evalsgrader-choice probe (verbatim, thinking-on, N=200, position-counterbalanced) + Betley (8×50) + UK AISI-200, on dpo_hacker + dpo_control. Judges via OpenRouter. Same instruments as the SFT baseline, so the comparison is like-for-like.
Stage 1 outcomedpo_hacker − dpo_control hasty-grader gap (Wilson CI, z-test) vs the SFT +17.5 pp; Betley / AISI gap vs floor. Gate: run Stage 2 only if the grader gap reproduces (CIs separated, ≥ ~ SFT).
Stage 2 evals (gated)MMLU (20/subject) + IFEval + Betley coherence, on dpo_hacker vs SFT our_hacker (re-serve the SFT adapter from lasr-extension-ariana/sorh-sft-qwen3-32b) and base. The "less broken" test.
Known confoundsno SoRH DPO recipe to match (SoRH is SFT-only), so β / lr are standard defaults, not tuned; single seed per condition; DPO pairs are the NL subset only (coding tasks excluded), a narrower distribution than SFT saw; "broken" is proxied by MMLU / IFEval / coherence, not a full capability battery.
Done whenStage 1: results/experiments/261114-sorh-dpo/grader_choice_think.json + output/evaluation/sorh-dpo-em/. Stage 2 (if gated in): output/evaluation/sorh-dpo-health/.
